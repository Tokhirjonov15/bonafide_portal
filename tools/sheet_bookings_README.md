# 물리치료센터 예약리스트(Google Sheet) → 동선관리 연동 — 설치 안내

`tools/sheet_bookings.gs`(Apps Script)가 **비급여 예약리스트** 구글 시트의 오늘·내일 탭을 읽어 동선관리 Firestore `bookings/{YYYY-MM-DD}` 에 올리고,
동선관리의 **4층 비급여 치료** 화면(상단 `예약관리` 단추, 전용 모니터는 주소 뒤에 `?resv`)에 **충격파 · 신장분사** 시간표(치료사별)와 **SASO · 자동차도수** 표(Manual Tx 명단)가 표시됩니다.
시트 자료는 직원용입니다 — **환자용 대기화면(TV)에는 내지 않습니다**(2026-09-15). 대기화면에서 이 네 방은 다른 방과 같은 보통 대기 목록입니다.
시트는 **읽기만** 합니다. 예약리스트 파일을 고치거나 쓰지 않습니다.

## 표시 규칙(4층 비급여 치료 화면)
- 열 = 그날 예약이 있는 치료사(시트 순서: Jack, Jennie, Hannah …), 행 = 30분. 60·90분 예약은 칸이 세로로 이어집니다.
- 칸 안: `치료코드` 이름 `차트번호` `방문수` `시간`. 시트에서 칠한 색은 작은 색 점으로(마우스를 올리면 뜻: 임시치료실 · 치료실 없음 · 시트·비트확인 · 실손 · 카톡친추).
- **도착**(연파랑 칸): 그 차트번호 환자가 보드에 카드로 있거나, 시트에서 연노랑(내원)으로 칠했을 때. **치료 중**(파랑): 카드가 그 방에서 진행 중.
- 회색 칸 = 시트의 근무 외/차단(`ot30분`, `점심당직` 등). 취소/변경 열의 환자는 그 시각 칸에 취소선으로.
- 화면 위 통계 카드: 비급여 예약 수·도착(내원)·취소·도수 예약·예약 치료시간 합, 치료사별·코드별 건수, 시트 아래쪽 숫자(당월 누적 상담수·평균 내원률·비급여 합계).
- 날짜를 바꾸면 그 날짜 문서를 읽어 옵니다(야간 동기화로 다음 7일이 준비됨). 인쇄는 표마다.
- 시트 메모(셀 코멘트)는 툴팁으로만. 예약이 없는 날은 예전처럼 방 배정 담당자 열로 표시합니다.

## 화면에서 예약 고치기(시트 없이도)
- 표의 예약 칸을 누르면 수정 창: 치료사·시간·치료시간·차트번호·성함·코드·메모. **취소 처리**(취소선으로 표시), **시트대로 되돌리기**. 빈 칸을 누르거나 **＋ 예약 추가**로 새 예약, 도수 표는 줄을 누르거나 **＋ 도수 추가**.
- 고친 내용은 Firestore `bookingEdits/{날짜}` 에 따로 저장되고 시트 문서 위에 겹쳐 보입니다(**시트에는 반영되지 않음**). 시트 쪽에서 그 예약을 고치면 키가 달라져 동선관리의 수정본은 저절로 빠집니다.
- 이 화면은 **보드 카드를 보지 않습니다**(예약만). 시트를 그만 쓰게 되면 이 문서(추가분)가 그대로 예약 원본이 됩니다 — Apps Script 만 끄면 됩니다.

## 1. 동선관리에 봇 계정 만들기 (한 번, admin 계정으로)
동선관리 → 계정 관리 → **계정 추가**: 아이디 `sheetbot`, 권한 `직원`, 비밀번호 8자 이상.
만든 뒤 Firebase 콘솔 → Authentication → Users 에서 `sheetbot` 줄의 **이메일**(`u…@bonafide.app` 꼴)을 복사해 둡니다. (bitbot과 같은 방식)

## 2. Firestore 규칙에 bookings 추가 (Firebase 콘솔 → Firestore → 규칙)
`bitplus_watcher_README.md` 8-2 의 전체 규칙(이미 bookings 블록이 들어 있음)을 붙여 넣고 `<sheetbot 이메일>` 만 바꿔 게시합니다.
핵심은 두 가지입니다:
```
    match /bookings/{day} {
      allow read: if request.auth != null;
      allow write: if request.auth != null && request.auth.token.email == '<sheetbot 이메일>';
    }
    // 마지막 공통 규칙은 봇 컬렉션을 제외해야 한다(겹치는 match 는 하나라도 허용이면 허용)
    match /{collection}/{document=**} {
      allow read, write: if request.auth != null
        && !(collection in ['bitIntake','bitStatus','bitLookup','bitNote','bookings']);
    }
```
확인: 직원 계정으로 bookings 문서를 쓰면 거부(403)돼야 정상입니다.

## 3. Apps Script 넣기 (예약리스트에 편집 권한이 있는 구글 계정으로)
1. 예약리스트 파일 열기 → 확장 프로그램 → **Apps Script** (이미 `getColorRatio` 가 있는 프로젝트가 열립니다. 그 코드는 건드리지 않습니다.)
2. 왼쪽 `+` → 스크립트 → 이름 `sheet_bookings` → `tools/sheet_bookings.gs` 내용 전체를 붙여 넣고 저장.
3. 왼쪽 톱니(프로젝트 설정) → **스크립트 속성** → 추가:
   | 속성 | 값 |
   |---|---|
   | `FIREBASE_API_KEY` | 동선관리 Firebase 웹 API 키 (`public/dongseon/index.html` 의 `apiKey`) |
   | `BOT_EMAIL` | 1단계의 sheetbot 이메일 |
   | `BOT_PASSWORD` | sheetbot 비밀번호 |
   | `FILE_ID` | (선택) 이 파일의 ID — 파일에 묶인 프로젝트라면 비워 두고 이름 규칙으로 찾게 해도 됨 |
   `FILE_NAME` 을 비우면 `비급여 예약리스트 {M}월({YYYY})` 이름을 가진 파일을 이번 달에 맞춰 찾습니다. 다음 달 파일 이름이 이 규칙을 따르면 아무것도 바꿀 필요가 없습니다.
4. 편집기 위 함수 선택에서 **`installTriggers`** 고르고 ▶ 실행 → 권한 요청 창에서 계정 선택 → "고급" → "이동" → 허용.
   (스프레드시트·드라이브 읽기, 외부 서비스 연결(Firebase), 트리거 권한입니다.)
5. 실행 로그에 `설치 완료. 파일: …` 이 보이면 끝. 동선관리 대기화면에서 충격파·신장분사 시트를 열어 오늘 예약이 보이는지 확인합니다.

## 4. 동작
- 파일이 바뀔 때마다(값·색·병합 모두) 오늘·내일 탭을 다시 올립니다(연속 편집은 8초에 한 번). 5분마다도 한 번 더.
- 매일 00:15 에 다음 7일 탭을 올리고, 새 달 파일이 생겼으면 변경 감지 트리거를 그 파일로 옮깁니다.
- 내용이 바뀌지 않았으면 쓰지 않습니다(Firestore 쓰기 절약).
- 직원이 동선관리에서 지난/예정 날짜를 고르면 그 날짜 문서를 한 번 읽어 옵니다(야간 동기화로 7일치가 준비돼 있음).

## 5. 확인·문제
| 상황 | 조치 |
|---|---|
| 상태 보기 | 편집기에서 `status` 실행 → 트리거 목록, 마지막 오류(`lastErr`) |
| 특정 날짜 파싱 결과만 보기 | `previewDate('2026-09-13')` 실행(쓰지 않음) |
| `Firebase 로그인 실패` | 1단계 이메일·비밀번호 확인, 3단계 속성 오타 |
| `Firestore 쓰기 실패 403` | 2단계 규칙의 이메일이 sheetbot 과 같은지 확인 |
| `예약리스트 파일을 찾지 못함` | 파일 이름이 규칙과 다름 → `FILE_ID` 속성에 파일 ID 지정 |
| 시트 레이아웃이 바뀜(열 위치·시작 행) | `sheet_bookings.gs` 맨 위 `LAYOUT` 만 고쳐 저장(트리거 재설치 불필요) |
| 치료사 이름을 한글로 보이게 하고 싶음 | 시트 4행 이름을 바꾸면 그대로 따라감(동선관리에는 이름 변환표 없음) |

## 6. 개인정보
문서에는 시트에 적힌 차트번호·이름·치료코드·메모가 들어갑니다. 읽기는 동선관리 로그인 계정만 가능하고(규칙), 환자용 화면에는 이름을 가려 보여 줍니다.
Apps Script 는 편집 권한이 있는 계정(설치한 사람)의 이름으로 실행되므로, 그 계정이 예약리스트 접근을 잃으면 동기화가 멈춥니다(대기화면은 마지막 문서를 계속 보여 줌).
