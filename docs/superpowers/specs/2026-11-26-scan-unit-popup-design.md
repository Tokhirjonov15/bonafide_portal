# 스캔 입고·출고 단위/수량 한 팝업 — 설계 (짧은 설계, 승인됨)

대상: `public/jaego/index.html` 만 수정 (서버·DB 변경 없음)

## 목적 (왜)
품목마다 1박스 개수가 다르고 같은 품목도 박스로 들어올 때와 낱개로 들어올 때가 있다. 지금은 스캔마다
"단위 선택 → 다음 화면에서 수량 입력 → 확인" 3단계라 번거롭다. 단위 선택과 수량 입력을 한 팝업에 두고,
같은 바코드는 한 번 스캔한 뒤 수량만 넣어 한꺼번에 입고·출고한다.

## 목표 / 비목표
- 목표: 스캔 시 뜨는 팝업(`#outOvl`) 한 화면에서 [박스]/[개수] 선택 + 수량 입력 + 확인. 수량 칸이 바로 선택돼 숫자 입력 후 Enter로 끝.
- 비목표: 서버·기록 방식 변경(입고 `N박스`, 출고 개수 그대로), 재고 현황의 + 버튼 입고창(`#mvOvl`) 변경, 연속 스캔 방식 변경.

## 동작
- 박스 크기가 있는 품목: [박스 (1박스=N개)] [개수] 선택 버튼 + 수량 칸을 같이 보인다.
- 박스 크기가 없는 품목: 단위 버튼 없이 수량 칸만(개수).
- 처음 선택되는 단위: 그 품목에서 마지막에 쓴 단위(이 PC `localStorage` `jaego_unit_<pid>`), 없으면 입고=박스, 출고=개수. 내 판단.
- 환산 힌트("= 30개 입고 → 재고 77", 출고가 재고보다 많으면 경고)와 재고 초과 출고 확인창은 기존 그대로.
- 확인 시 기존 `outGo` 경로: 입고 박스 `{qty:박스수, unit:"box"}`, 입고 개수 `{qty, unit:"ea"}`, 출고 `{qty:개수}`.

## 접근 방법
1. **기존 팝업의 1단계(단위 선택)와 2단계(수량)를 한 화면으로 합친다 (선택)** — 변경 최소, 서버 영향 없음.
2. 새 팝업을 따로 만든다 — 중복 코드, 기존 키보드 처리(Esc/Enter)와 어긋날 위험.
3. 단위 선택 없이 수량에 "3박스"처럼 글자로 입력 — 스캐너·터치 환경에서 오입력 위험.

## 테스트
- 단위·수량 계산·기본 단위 결정은 순수 함수로 분리해 Node 테스트(`tests/jaego/`)로 검증:
  `defaultUnit(mode, boxSize, lastUnit)`, `unitCount(unit, qty, boxSize)`.
- 팝업 화면 동작은 localhost 정적 서버에서 `scanOutAsk` 호출로 눈으로 확인(서버 없음 → `/scan` 은 흉내).

## 구현자에게 맡기는 것
순수 함수 파일 위치(기존 `inbound-labels.js` 와 같은 방식의 별도 파일), 선택 버튼 마크업·스타일 세부.
